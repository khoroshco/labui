# 0006. `node --test` вместо vitest, зависимости по счёту

**Статус:** принято · шаг 5 переезда

## Контекст

В плане переезда стоял vitest. Node 22 умеет тот же объём встроенным `node:test`: describe/it, ассерты, отчёт TAP, параллельный прогон.

## Решение

Unit-тесты идут на `node --test`. Стенд (`tests/unit/harness.mjs`) поднимает класс компонента прямо из `.dc.html` с заглушкой `DCLogic` и повторяет то, что делает рантайм: `{...props, ...renderVals()}`.

## Последствия

- Минус зависимость и минус её транзитивное дерево. Для инфраструктурной библиотеки, которую ставят в чужие приложения, каждая зависимость — налог на потребителя.
- Тесты быстрые (44 проверки за 0.13 с) и не требуют сборки.
- Цена: нет `expect`-матчеров и watch-режима из коробки. На этом объёме не мешает.
- Стенд переживёт миграцию: `renderVals()` в Фазе 3 становится телом функционального компонента, и те же тесты становятся приёмкой.
