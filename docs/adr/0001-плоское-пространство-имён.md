# 0001. Плоское пространство имён URL при раскладке по уровням

**Статус:** принято · шаг 2 переезда

## Контекст

`support.js` монтирует вложенный компонент как `./Имя.dc.html` **относительно открытого документа** (`COMPONENT_DIR = "."`), а теги из `<helmet>` копируются в head того же документа. Значит `tokens.css`, `svgs/plus.svg` и соседние компоненты обязаны разрешаться из одной точки.

Целевая раскладка из плана переезда (`src/atoms/`, `src/molecules/`, `src/organisms/`, `storybook/`) этому противоречит напрямую: при ней не работает ничего — ни витрина, ни standalone-страница компонента.

## Решение

Раскладка по уровням остаётся — она для читателя. URL остаются плоскими — они для рантайма. Перевод одного в другое живёт в одном месте: `scripts/vite-plugin-flat-ds.mjs` (дев-сервер) и `scripts/build-site.mjs` (статика). `/Button.dc.html` → `src/atoms/Button.dc.html`, `/svgs/*` и `/fonts/*` — как есть.

## Последствия

- **Имя компонента уникально во всём `src/`.** Коллизия роняет дев-сервер на старте — это лучше тихой подмены файла.
- В хелметах пишутся только голые имена: никаких `../` и никаких путей с уровнем.
- Дев и статика отдают одно дерево URL, поэтому гейты и живой сайт смотрят на одно и то же.
- Файлы отдаются байт в байт, до внутренних middleware Vite: HTML не проходит через `transformIndexHtml`, иначе Vite переписал бы href в хелметах и подмешал свой клиент.

## Альтернативы

- **Плоская раскладка на диске.** Работает без машинерии, но теряет уровни — а уровни это состав системы, и в Фазе 2 они всё равно нужны в `api.json`.
- **Абсолютные пути в хелметах.** Ломаются на GitHub Pages, где сайт живёт в подкаталоге.
- **Патч рантайма.** `support.js` сгенерирован; правка исчезнет при следующей выгрузке.
