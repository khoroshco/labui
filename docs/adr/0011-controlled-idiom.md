# 0011. Управляемость по значению, а не по колбэку

**Статус:** принято · Фаза 3 · breaking change относительно DC-версии

## Контекст

В DC-версии признаком управляемости было наличие колбэка: `typeof onChange === 'function'`. В React общепринято другое: значение задано (`value` / `checked`) — контрол управляемый; задан только `defaultValue` / `defaultChecked` — контрол ведёт своё.

Схемы близки, но не тождественны, и различие всплывает ровно там, где больно: родитель, который хочет ТОЛЬКО слушать (передал колбэк, но значением не владеет), в старой схеме замораживал контрол.

## Решение

Все шесть контролов (Toggle, Checkbox, OptionGroup, Tabs, CycleButton, Disclosure) переходят на React-идиому одним решением. Реализация — общий хук `useControlled`, чтобы правило нельзя было исполнить по-разному в разных компонентах.

Инвариант при этом прежний и проверяется тестами: пока значение приходит сверху, контрол показывает РОВНО его; без значения ведёт своё, а `defaultValue` работает начальным.

## Последствия

- Это **мажор** относительно DC-версии. Ни один сервис к ней не подключён — цена решения нулевая, и именно поэтому оно принимается сейчас, а не после публикации.
- Слушать, не владея, теперь можно: колбэк без значения больше не замораживает контрол.
- `Input` и `Slider` остаются особыми: набор и перетаскивание обязаны быть живыми, поэтому они всегда ведут своё значение, а проп задаёт начальное и перекрывает своё, когда приходит новым.
