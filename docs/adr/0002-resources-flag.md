# 0002. Флаг `window.__resources = {}` в каждой странице

**Статус:** принято · шаг 3 переезда

## Контекст

`RowLabel.dc.html` не рендерился вообще: вместо компонента рантайм показывал заглушку «removeChild … not a child of this node». В витрине этого не видно — там RowLabel монтируется как ребёнок, и падающий путь не задействован.

Причина внутри `boot()`: он перечитывает документ вторым запросом (`fetch(location.href)`) и пересобирает шаблон поверх уже смонтированного дерева. Разница между двумя разборами — **только регистр имён атрибутов** (`onClick` → `onclick`), и его рантайм нормализует сам через `EVENT_MAP`. Проверено на всех 29 страницах: других отличий нет.

## Решение

`<script>window.__resources = {};</script>` в голове каждой `.dc.html`, до `support.js`. Это собственная ручка рантайма: все её ветки при пустом объекте уходят в те же дефолты, а второй проход не выполняется.

## Последствия

- Компонент рендерится один раз вместо двух — меньше гонок, стабильнее тесты.
- Флаг лежит в файлах, а не в стенде: страница работает так же под любым статическим сервером.
- Если следующая выгрузка из дизайн-инструмента затрёт флаг, smoke покраснеет на RowLabel — регрессия не будет тихой.

## Альтернативы

- **Инъекция флага сервером.** Тогда «работает» зависит от способа подачи, и файл, открытый другим сервером, снова ломается.
- **Правка `support.js`.** Запрещена: рантайм сгенерирован.
- **Оставить как есть.** Один компонент из 27 не работает standalone — то есть не проверяется ни визуально, ни a11y.
