# 0009. Источник токенов — файл в формате DTCG, `tokens.css` становится артефактом

**Статус:** принято · Фаза 1

## Контекст

Значения жили в `src/tokens.css`, и он же был единственным источником. Пакет `@khoroshco/tokens` разбирал этот CSS регулярками — то есть формат обмена выводился из формата доставки. Любой второй потребитель (Figma, Style Dictionary, Swift/Kotlin) начинался бы с ещё одного парсера CSS.

W3C DTCG получил стабильную версию в октябре 2025 и поддерживается Figma, Tokens Studio, Style Dictionary, Terrazzo. Для формата обмена «скучный стандарт» — лучшее свойство.

## Решение

Источник истины — `tokens/banner-lab.tokens.json`. Из него собираются `src/tokens.css` (артефакт, в `.gitignore`) и пакет `@khoroshco/tokens`.

Конвертер, которым источник переносили из CSS, удалён после переноса: он одноразовый, а его происхождение живёт в истории git. Оставлять исполняемый скрипт, который больше никогда не запускается, — тот же долг, что и устаревшее правило.

**Правила отображения**, которые пришлось выбрать явно:

- **Имя листа = имя CSS-переменной без `--`.** Спецификация выводит имя из пути группы; у нас имена уже опубликованы и переименование = мажор, поэтому путь несёт слой (`primitive` / `alias` / `theme.light`), а имя остаётся своим.
- **Слои — группы, ссылки — синтаксис DTCG.** `{primitive.c-gray-950}` разворачивается в `var(--c-gray-950)`. Трёхслойная схема переносится один в один, как и требует ROADMAP: сплющивать нельзя, на ней держится половина устойчивости.
- **Примитив — тот, у кого сырое значение.** Имя не признак: `--k-accent` зовётся как примитив, но ссылается на другой токен и перемапливается темой, то есть по смыслу алиас.

## Чего спецификация не умеет, и что мы с этим сделали

Половина алиасов — CSS-выражения, а не литералы: `rgb(var(--ink) / .48)`, `linear-gradient(135deg, …)`, `linear(0, 0.062 5%, …)`, многослойные тени. Это не небрежность, а механизм: тема переопределяет **два** чернильных канала вместо двенадцати токенов, и именно поэтому светлая тема — 23 строки, а не 95.

Выразить такое в чистом DTCG нельзя: у типа `color` нет ссылки с переопределением альфы, у `cubicBezier` нет `linear()`. Варианты были два — сплющить механизм в перечисление значений на тему (и потерять то, ради чего он есть) или пометить такие значения расширением. Выбрано второе: `$extensions["com.bannerlab.css"].expression = true`. Расширения — первоклассный механизм спецификации, а не обход.

**Следствие, которое надо знать:** файл валиден по структуре DTCG, но не пройдёт строгую проверку типов у инструмента, который потребует от `color` спецификационной формы значения. Инструмент, читающий `$extensions`, получит рабочие значения; инструмент, читающий только `$value`, получит корректный CSS.

## Последствия

- Значение живёт в одном месте; `tokens.css` собирается на старте дев-сервера, перед сборкой сайта и после `npm ci` (`prepare`).
- Гейт `lint:tokens-source` держит: ссылка ведёт в существующий токен, у токена есть `$type`, тема переопределяет только алиасы и только существующие, орфанов нет, собранный CSS не разошёлся с источником. Проверен на красноту по каждому пункту.
- Переименование токена — мажор: имя ушло к потребителю вместе с пакетом.
- Фаза 3 (React) получает токены из того же источника: `TOKENS` типизированы, опечатка в имени не проходит компиляцию.
