# Документы системы

| файл | о чём | кто обновляет |
|---|---|---|
| [design-system.md](design-system.md) | правила дизайна: типографика, цвет, движение, состояния, словарь, композиция | тот, кто меняет правило — тем же коммитом |
| [repository.md](repository.md) | механика: раскладка, токены, контракт, что нельзя трогать | тот, кто меняет механику |
| [gates.md](gates.md) | что держит каждый гейт и как заставить его покраснеть | тот, кто заводит или меняет гейт |
| [consumer.md](consumer.md) | как подключить систему к сервису | тот, кто меняет публичный API |
| [adr/](adr/) | решения, которые не надо переигрывать | новая запись, а не правка старой |

Переездные документы (исходное задание, хендофф, процесс до репозитория) удалены: их
содержание либо исполнено, либо переехало сюда. История — в git.

**Правило одно:** документ обновляется ТЕМ ЖЕ коммитом, который меняет реальность.
Разошедшийся документ — не неточность, а ложное правило, которое следующий агент исполнит
буквально. Что можно вывести из кода — выводится, а не описывается.

## Чего здесь нет и не будет

**Отчётов ревизий и консилиумов.** Находка — это работа, а не знание: она живёт в трекере,
пока её не закрыли, и исчезает вместе с закрытием. В документах остаётся только то, что
переживёт находку: правило, которое из неё вывели, и гейт, который это правило держит.
Иначе `docs/` превращается в архив вчерашних проблем, и следующий читатель не может
отличить действующее правило от протокола давно закрытого спора.
