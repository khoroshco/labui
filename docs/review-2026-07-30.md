# Ревью 30.07.2026: находки и их состояние

Четыре независимых ревьюера без общего контекста прошли по React-компонентам, гейтам, инфраструктуре и сверке документов с кодом. Файл ведётся до закрытия последней строки: **пока строка не «закрыто», её нельзя считать сделанной.**

Главный вывод ревью, который стоит помнить дольше любой отдельной находки: **паритет был объявлен доказанным, а доказан был только статический вид дефолтного состояния.** Поведение, состояния и композиция оставались непокрытыми, а порог снимка (`maxDiffPixelRatio` от полной ширины 1280px) допускал до 675 отличающихся пикселей у острова.

## Осталось (по убыванию риска)

1. **Собранный пакет `@banner-lab/ds` не загружается в Node.** `moduleResolution: "bundler"` даёт импорты без расширений при `"type": "module"`. Vite терпит, SSR и node-окружение — нет. Нужно `nodenext` + `.js` в импортах исходников и `await import(dist/index.js)` в конце сборки, чтобы падало у нас, а не у потребителя.
2. **Все шесть ченджсетов адресованы `@banner-lab/tokens`**, хотя описывают React, паритет, слайдер и витрину. `changeset version` дал бы токенам 0.2.0 с чужим CHANGELOG, а реальную работу не версионировал бы вовсе. Перецелить на `@banner-lab/ds`, инфраструктурные удалить, DTCG-запись понизить до patch.
3. **Корневой пакет и React-пакет носят одно имя** `@banner-lab/ds` (0.1.0 и 0.0.0). Переименовать корень.
4. **Вложенная DTCG-ссылка молча уезжает в CSS мусором**: разворачивается только `{группа.имя}`, и тот же однонивелевый регексп служит гейтом. Нужен обход любой глубины и assert «в выводе не осталось `{…}`».
5. **Нет гейта между `icons.generated.ts` и `src/svgs/`**: удалённая иконка в DC не рисуется, в React рисуется старая. Нужен `build-icons --check` в `lint`.
6. **Гейт иконок не видит, как иконки передаются на самом деле** (`icon="…"` на `dc-import`, проп с именем): удаление `src/svgs/trash-bin.svg` проходит все линтеры зелёными.
7. **pa11y зеленеет на пустом списке URL** (`buildFlatMap(process.cwd())` + нет проверки длины) и **смотрит страницы с дефолтными пропсами**: остров, карточка пинов и скелетон отдают пустой div, у группы опций и ряда нет ни одного контрола. Нужны корень от `import.meta.url`, `if (urls.length < 20) throw` и фикстуры через `?props=`.
8. **`build-site.mjs` берёт корень из `cwd`**: запуск не из корня молча деплоит пустой сайт и делает `rm -rf` по cwd-пути.
9. **`check-tokens-source` сам чинит то, о чём докладывает** (пишет файл и возвращает «изменилось»), а в CI мёртв: `prepare` уже пересобрал `tokens.css`. Сравнивать без записи.
10. **Ledger дыр шаблона не краснеет на устаревшую запись** — в отличие от двух a11y-ledger'ов, где такая проверка есть и работает.
11. **a11y-ledger записан по id правила без числа узлов**: новое нарушение того же класса в том же компоненте проглатывается (проверено перекраской опции в `--warn`).
12. **Две копии FIXTURES** (`tests/support/fixtures.js` и внутри `axe.spec.js`) уже разошлись: визуальный эталон и проверка доступности смотрят разные состояния.
13. **smoke не отличает «смонтировался» от «нарисовал пустоту»**: у острова 2 узла при высоте 0 — зелено.
14. **Коммерческие шрифты Unica 77 уезжают сырыми OTF на публичный Pages** (`dist-site/fonts/*.otf`). `LICENSE` в репозитории нет, пакеты объявляют `UNLICENSED` вместе с `publishConfig.access: public`. **Решение за владельцем**: убрать шрифты из статики (витрина уедет на системный шрифт), закрыть Pages или оставить осознанно.
15. **Тарбол тащит sourcemap'ы, указывающие за пределы пакета**, а `dist/ds.css` ссылается на три шрифта, которых в тарболе нет: потребитель по README получает системный шрифт и вся оптика уезжает.
16. **`@types/react@19` против `react@18`** — типы описывают не тот React, который исполняется.
17. **Голый `npx tsc` / `npx pa11y-ci`** при неполном `node_modules` тянет пакет из реестра (`tsc` в npm — чужой пакет). Нужен `--no-install` или `node_modules/.bin`.
18. **`npm audit`: 5 high** через `brace-expansion → … → pa11y-ci`. Только dev. **`npm audit fix --force` понизит pa11y-ci 4.1.1 → 1.2.0 — не запускать**, ставить `overrides`.
19. **Документы отправляют правку в замороженный эталон**: `CONTRIBUTING.md:9,65`, `README.md:65` говорят «меняй в `src/`». Самое опасное для AI-контрибьютора.
20. **`CLAUDE.md`**: идиома Disclosure описана по-старому (`onToggle` вместо `open`), «maxLength со счётчиком» противоречит «без счётчика», `150px` вместо `160px` у картинки RowInfo, состав витрины без Skeleton/PinComposer/EmptyState, весь `src/` назван замороженным (а `ds.css`, `svgs/`, `fonts/` — живые входы React-пакета), список гейтов неполон.
21. **`api.json` и `types.d.ts` описывают эталон** (`runtime: dc`), в них нет `default*`-пропсов React — потребитель решит, что неуправляемый режим невозможен. Нужно либо генерировать контракт из `.tsx`, либо честно назвать снапшот эталонным.
22. **`ROADMAP.md`** описывает харнесс шире, чем он есть (forced-colors, вычисленные стили, ARIA-дерево, хит-зоны в паритете отсутствуют), и обещает удаление эталона, которое противоречит ADR 0012. Не помечен частично исполненным.
23. **ADR 0010** утверждал, что `lint:tokens` читает `.tsx` — теперь читает, но фразу стоит перечитать; **ADR 0012** переоценивает охват паритета.
24. **`docs/process.md`** не помечен исполненным и называет `tokens.css` источником истины.
25. **`packages/ds-react/README.md`**: рекламирует `npm i` непубликуемого пакета и объясняет заморозку контрола обратной причиной.
26. **Рецепт «как добавить компонент»** (`CONTRIBUTING.md`, `CLAUDE.md`) неисполним ни для эталона (заморожен), ни для React (`build-api.mjs` его не видит).
27. Мелкое: `check-showcase` не допускает цифр в имени компонента; `check-vocabulary` ломается на записи альфы `0.76`/`76%` и даёт ложное «лестница сломана»; `build-tokens` порог `< 50` при 127 токенах; `run-pa11y` пишет конфиг по предсказуемому пути и не обрабатывает `child.on('error')`; `playwright.config.js` с `reuseExistingServer` подключается к чужому серверу на :5173.

## Как продолжать

Порядок: пункты 1–3 (пакет и версии) → 4–13 (гейты) → 19–26 (документы) → 27. Пункт 14 — вопрос владельцу, а не задача.

После каждой правки: `npm run verify`, ченджсет, PR. Гейт обязан сначала покраснеть на находке и только потом позеленеть на исправлении — ревью показало, что обратный порядок даёт зелёный гейт над сломанным кодом.
