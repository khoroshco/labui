# Banner Lab × Claude — процесс работы

## Принцип
Дизайн-система (ДС) — единственный источник визуальной истины. Продуктовые экраны Banner Lab — только композиция готовых компонентов. Ноль локального визуала на экранах.

## Источники истины
- **tokens.css** — цвет, типографика, отступы, радиусы, тени, движение. Любой цвет/размер — только токеном.
- **ds.css** — глобальные состояния (пресс, фокус, тултипы, сепараторы островов, кейфреймы).
- **Компоненты `*.dc.html`** — по одному файлу на компонент, без бизнес-логики: данные и колбэки пропсами.
- **Storybook.dc.html** — витрина и спека: уровни Примитивы → Атомы → Молекулы → Организмы, у каждого компонента плейграунд со всеми пропсами (неочевидные — с ⓘ).
- **CLAUDE.md** — контракт правил. Claude Code читает его автоматически в начале каждой сессии; всё, что решили — фиксируется туда, иначе решение потеряется.

## Два типа сессий
1. **ДС-сессия** — работа над компонентами. Итог всегда виден в Storybook; правило «каждая правка = обновлённая витрина + правило в CLAUDE.md».
2. **Продуктовая сессия** — экраны Banner Lab (сетка приёмки, шлюз нарезки, канвас). На вход Claude даётся: ссылка на Storybook (спека пропсов) + запрет создавать новые визуальные элементы. Не хватает компонента → сначала ДС-сессия, потом экран.

## Цикл фичи
1. Сформулировать, какие компоненты нужны → проверить в Storybook.
2. Нет компонента → добавить в ДС (компонент + секция + плейграунд + правило).
3. Собрать экран композицией. Данные — пропсами сверху, состояние — у экрана.
4. Приёмка: прогон Storybook (ничего не сломано) + прогон экрана.

## Технические правила
- В хелметах — голые имена файлов, без `?v=N`. Ручной кэш-бастинг был механизмом среды без сборки; в репозитории он удалён (см. раздел «Репозиторий» в `CLAUDE.md`).
- Жёсткая перезагрузка (Cmd+Shift+R) при подозрении на устаревшие компоненты.
- Нейминг пропсов — по словарю из CLAUDE.md (label/text/value; checked; variant — иерархия, tone — семантика, level — серьёзность сообщения; tooltip). Оси `state` в системе нет — она ушла вместе с компонентом Status. Сепаратор рисует остров — своего пропа у рядов нет.
- Валидация, загрузка, disabled — по правилам CLAUDE.md, не изобретать на экране.

## Git
- ДС — отдельный репозиторий (`khoroshco/labui`), не связанный ни с одним сервисом. Экраны — отдельно; дифф компонентов виден в ревью отдельно от экранов.
- Каждая ДС-правка — маленький коммит «компонент: что изменилось»; Storybook — приёмочный артефакт в PR.
- Ревью человеком нет: качество держат гейты. Мёрж только через PR, красный прогон блокирует мёрж.
