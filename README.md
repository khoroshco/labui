# Banner Lab DS

Дизайн-система Banner Lab: 27 компонентов, токены, витрина-спека. Код рабочий, а не мокапы — открывается в браузере и соблюдает свои правила.

**Живая витрина:** https://khoroshco.github.io/labui/

Весь код здесь пишет AI, ревью человеком нет. Поэтому надёжность держится не на внимательности, а на автоматике: около 290 проверок на каждый PR, красный прогон блокирует мёрж.

## Запуск

```bash
npm ci
npm run dev
```

Витрина откроется на `http://localhost:5173/`. Нужен Node из `.nvmrc`.

```bash
npm run verify    # все гейты разом, ~2 минуты
```

```
                     живые входы обеих реализаций: ds.css, svgs/, fonts/, собираемый tokens.css
  atoms/             Button, Input, Checkbox, Toggle, CycleButton, OptionGroup, Badge, Skeleton, Avatar, Pin
  molecules/         RowLabel, RowInfo, RowMsg, InputRow, ChoiceRow, SwitchRow, CheckboxRow, ActionRow,
                     Slider, Disclosure, Segments, Tabs, Toast, PinCard, PinComposer
  organisms/         Island, EmptyState

packages/tokens/     @khoroshco/tokens — единственный публикуемый пакет
tokens/              источник токенов в формате W3C DTCG; src/tokens.css из него собирается

```

Раскладка по уровням — для читателя. Рантайм монтирует компоненты по **плоскому** пространству имён (`/Button.dc.html`, `/tokens.css`, `/svgs/*`); перевод одного в другое делают дев-сервер и сборка сайта. Почему так — [ADR 0001](docs/adr/0001-плоское-пространство-имён.md).

## Гейты

| гейт | что держит |
|---|---|
| `lint:tokens-source` | источник DTCG: типы, ссылки в никуда, слои, орфаны; `tokens.css` собран из источника |
| `lint:tokens` | ни одного литерального цвета, изинга, веса, интерлиньяжа; примитивы `--c-*`/`--k-*` не напрямую — и в `.dc.html`, и в `.tsx` |
| `lint:props` | проп объявлен ⇔ читается; колбэк без пропа-значения замораживает контрол |
| `lint:api` | `api.json` не разошёлся с исходниками эталона |
| `lint:icons` | `icons.generated.ts` не разошёлся с `src/svgs/` |
| `lint:vocabulary` | словарь имён пропсов, существование иконок, монотонность лестницы яркости |
| `lint:showcase` | витрина строится из `api.json` и не называет несуществующего |
| `typecheck` | типы React-пакета и харнесса |
| `test:unit` | управляемый режим шести контролов, композиция рядов, магнит слайдера, состав валидации, ledger'ы |
| `test:smoke` | каждая страница грузится без ошибок, со шрифтом и с компонентом, который что-то нарисовал |
| `test:visual` | disabled, хит-зоны, оптическая центровка по ink-центру, структура + 81 снапшот в двух темах и reduced-motion |
| `test:parity` | React против эталона: снимки, точная сверка разметки и геометрии, поведение |
| `test:a11y` | axe в обеих темах, pa11y-ci (WCAG2AA) по страницам и по React с фикстурами, бюджет контраста на токенах |

Что проверяли независимые критики и что осталось — [docs/council-2026-07-30.md](docs/council-2026-07-30.md).

Известные отклонения не выключают гейт, а лежат в четырёх ledger'ах с объяснением и измеренным значением — [ADR 0004](docs/adr/0004-ledger-вместо-выключенного-гейта.md).

## Публикация

Пакеты уезжают в **приватный реестр GitHub Packages** — они для своих сервисов, а не для всех. Потребителю нужны две строки в `.npmrc` и токен GitHub с правом `read:packages`:

```
@khoroshco:registry=https://npm.pkg.github.com
//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}
```

Публикация происходит сама: ченджсеты считают версии, релизный workflow публикует встроенным токеном — заводить секрет вручную не нужно.

Публикуются оба: [`@khoroshco/tokens`](packages/tokens/README.md) и `@khoroshco/ds`. До миграции публиковались только токены — компоненты на DC-рантайме связали бы сервисы со старым форматом, и переход на React стал бы согласованным мажором во всех сразу. Эта причина исчерпана; почему теперь публикуем и почему приватно — [ADR 0003](docs/adr/0003-не-публикуем-компоненты.md).

## Правки

Читай `CONTRIBUTING.md`. Коротко: `CLAUDE.md` → правка в `packages/ds-react/src/` →
`npm run verify` → ченджсет → PR. `src/` — замороженный эталон, компоненты в нём не правят
(живые входы обеих реализаций — `ds.css`, `svgs/`, `fonts/`). Никогда не редактируй
`support.js` и не обновляй визуальные снапшоты, не посмотрев на диффы.
