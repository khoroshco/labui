# @khoroshco/ds

## 0.3.0

### Minor Changes

- bd8f65c: Уроки Base UI: связность формы, чужие клавиши, режим управления.

  **Режим управления фиксируется на монтировании.** Признак управляемости вычислялся на
  каждом рендере, и потребитель, у которого значение однажды становилось `undefined`
  (условный рендер, сброс формы, `?? undefined` в маппинге данных), получал не «контрол
  повёл своё», а `defaultValue`, замороженный при монтировании, — состояние, которого не
  было ни у кого на экране. Смена режима теперь предупреждает в консоли.

  **Ошибка связывается с контролом, а не объявляется живой областью.** Три невалидных ряда
  в острове давали три `assertive`-объявления в один тик: они перебивали друг друга и всё,
  что диктор читал в этот момент, а при возврате в поле не звучало ничего. Теперь
  `aria-describedby` от контрола к тексту — ошибка звучит при фокусе, по одной, и звучит
  повторно. У группы опций появилось имя ссылкой на подпись ряда.

  **Клавиши, которые принадлежат не нам.** Enter у чекбокса и тумблера отправляет форму, а
  переключает пробел — мы перехватывали обе и гасили событие. Стрелка с Ctrl/Alt/Meta —
  системное сочетание браузера, группы опций и лента вкладок съедали их не глядя. У слайдера
  появились Home, End, PageUp и PageDown. Мышиный клик по ряду больше не снимает фокус:
  следующий Tab начинал обход с начала документа.

  **Тост** останавливает отсчёт по фокусу внутри и по уходу из окна — сообщение, истекшее в
  другой вкладке, потеряно, — и закрывается по Escape. **Раскрывашка** ссылается на панель
  только когда та раскрыта, и панель получила имя.

- 915dac5: `ref` прокидывается на корень каждого компонента.

  Без него потребитель добирался до узла запросом по DOM из своего кода — то есть
  пользовался системой мимо контракта. Теперь `ref` приезжает на КОРЕНЬ, а не на внутренний
  узел: поставить фокус, померить, привязать поповер.

  Пять компонентов держат корневой ref для своих нужд (`OptionGroup` и `Tabs` меряют им
  скользящую подложку, `Slider` крутит желе, `Input` перезапускает анимацию отказа,
  `PinComposer` ставит автофокус) — там внешний ref не отнимает внутренний, узел получают оба.

  Держит `tests/parity/ref.spec.js`: ни один другой гейт ref не видит — в DOM он не атрибут,
  и ошибка «приняли, но никуда не поставили» прошла бы молча.

- 381deb4: Остров принимает детей, ряды получили каналы наружу, поле стало элементом формы.

  **`IslandRow` — размеченное объединение.** Прежний мешок необязательных полей пропускал
  бессмыслицу молча (`{ type: 'toggle', maxLength: 60, optionIndex: 7 }` проходил проверку
  типов) и мешал законному коду: `onChange` был объединением двух функциональных типов,
  поэтому вывод параметра не работал вовсе — каждый обработчик приходилось аннотировать
  руками, а `(index: number) => …` на ряду-переключателе компилировался и падал в рантайме.

  **Остров принимает `children`.** Раньше их выбрасывало молча, причём проверку типов это
  проходило. Конфиг покрывает пять типовых рядов; всё остальное потребитель приносит сам и
  получает ту же обёртку-маунт — иначе сепараторы и радиусы крайних рядов пришлось бы
  воспроизводить копированием `ds.css`.

  **У рядов появились `id`, `className`, `data-*` и `aria-*`** на корне. Без них форма не
  могла ни проскроллить к невалидному полю, ни пометить конкретный ряд.

  **`Input` стал элементом формы:** `name`, `type`, `autoComplete`, `inputMode`, `required`,
  `readOnly`. Без `name` не работали ни `FormData`, ни автозаполнение, ни менеджеры паролей.
  Сообщение валидации связано с полем через `aria-describedby`: раньше скринридер на
  возврате в поле говорил «недопустимое значение» и не говорил почему.

  **Пакет ставится в любой стек:** директива `"use client"` (без неё Next.js App Router ронял
  сборку на первом импорте), вторая сборка в CommonJS и вход `require` (Jest по умолчанию
  работает в CJS и падал с `ERR_REQUIRE_ESM`), поля `main`/`module`/`types`. Из тарбола убраны
  исходники и карты. Обе точки входа проверяются гейтом на реальную загрузку.

### Patch Changes

- 80d039c: Внутренние кнопки больше не отправляют форму потребителя.

  Шесть компонентов рендерили голый `<button>`, у которого браузерный дефолт `type` —
  `submit`: таб, раскрывашка, опция группы (значит и `Segments`, и `ChoiceRow`), циклер,
  кнопка ⓘ ряда, крестик очистки поля. Клик по табу внутри `<form>` отправлял её, и код
  потребителя при этом выглядел безупречно. Трёх из шести спасал `preventDefault`,
  написанный для других целей, — то есть случайно. Публичный `Button` знал об этом и ставил
  `type` сам; остальные — нет. Держит гейт: `<button>` без `type` в исходниках пакета красит
  `lint:props`.

  Шипаемый `ds.css` подключает токены сам. Забытый `tokens.css` ломал систему целиком —
  без переменных инлайновые стили не дают ни поверхностей, ни рамок, ни шрифта, — а
  `docs/consumer.md` обещал, что «просто пропадут фокус-кольца». Теперь забыть нельзя.

- db2a338: Слитый `ref` больше не дребезжит.

  У пяти компонентов, где внешний ref сливается с внутренним, колбэк задавался инлайном и
  пересоздавался на каждый рендер — React честно звал старый с `null`, и наружу уезжала
  череда «узел, null, узел». Для `react-hook-form` (заявленная причина, по которой ref вообще
  прокинут) `ref(null)` снимает поле с учёта: оно «размонтировалось» на каждое нажатие
  клавиши. Колбэк мемоизирован.

  Попутно в `ds.css`: фокусная рамка поля наконец применяется (объявление проигрывало
  инлайновому стилю, и переезд на токен `--focus` доехал только до React), кегль ввода на
  таче больше не переопределяет чужие инпуты потребителя, сброс тонировки в
  Windows High Contrast перестал проигрывать по специфичности.

## 0.2.2

### Patch Changes

- 4d19c3f: Компоненты переживают данные, которых не ждали.

  Все четыре пункта — про потребителя, а не про витрину: витрина кормит компоненты
  аккуратными наборами, поэтому ни один гейт таких состояний не видел.

  **Пустой список — это данные.** `Tabs` и `CycleButton` подставляли демонстрационный набор
  и на пустой массив: пока список грузится, лента уверенно показывала «Все форматы 18».
  Теперь демо-набор появляется, только когда набора нет вовсе; пустой массив значит
  «вариантов нет». Правило записано в контракт.

  **`Slider`** — шесть дыр разом: перетаскивание стартовало с любой кнопки мыши (правый клик
  утаскивал значение к курсору); нулевая ширина контейнера давала `NaN` навсегда;
  `max === min` ломал заливку и засечки; дробный `snapStep` плодил десять тысяч узлов; шаг
  считался от нуля, а не от `min` (при `min=10, step=3` стрелка давала 12 — значения, которого
  в шкале нет); отмена указателя не снимала перетаскивание.

  **`PinComposer`** — проп `value` работал ровно один раз, при монтировании: композер выглядел
  управляемым и им не был (ADR 0011). Пустая отправка уходила наружу как `onSend('')` —
  теперь как `onCancel`: у пинов это «передумал», и пустой пин обязан исчезнуть.

  **`Icon`** — имя `"toString"` из чужого JSON доставало с прототипа функцию и роняло рендер
  целиком. Теперь неизвестное имя оставляет пустое место, как и обещал контракт.

- dce66b5: Статус компонента в React-контракте по умолчанию — `unknown`, а не `stable`.

  `stable` по умолчанию — это обещание зрелости, выданное молча: новый компонент объявлял
  себя устоявшимся, ничего для этого не сделав. В контракте эталона дефолт всегда был
  `unknown`; теперь они совпали.

- c98cd6b: Фокус-кольцо, сепараторы и режимы системы.

  **Кольцо фокуса.** Рисовалось двумя слоями `box-shadow`, и внутренний слой заливал зазор
  цветом полотна: на карточке вокруг фокуса светилось гало размером с кольцо — подделанный
  фон. Теперь `outline` + `outline-offset`: зазор настоящий, размер элемента по-прежнему не
  меняется. Ряды острова и слайдер обрезаны `overflow:hidden` — им остаётся inset-вариант.

  Цвет кольца — свой токен `--focus`, а не `--accent`. Жёлтое кольцо на светлой бумаге
  давало **1.52:1** при норме **3:1** для нетекстового индикатора (WCAG 1.4.11) — то есть
  индикатора фокуса в светлой теме не было. Синий даёт 7.0:1 в тёмной теме и 4.5:1 в
  светлой. Тем же цветом набирается фокусная рамка поля: индикатор один — значит и цвет один.

  **Сепараторы острова** перечёркивали inset-кольцо сфокусированного ряда сверху и снизу.
  Гашение линий было написано по самому ряду, у которого границы нет вовсе; сепаратор рисует
  обёртка-маунт. Переписано по обёртке.

  **prefers-reduced-motion.** Общее правило гасит анимации до 0.01 мс. Там, где анимация —
  единственный носитель сообщения, это отбирало не движение, а само сообщение: упор в
  `maxLength` (события о заблокированном символе браузер не даёт вовсе) и спиннер кнопки
  (без вращения — статичная дуга). Оба выписаны как явные исключения.

  **forced-colors.** Тултип, `Toast` и `PinCard` отделены от полотна тенью, а режим её
  вырезает — плашка сливалась с тем, что под ней. Край возвращает граница.

- 36d80a8: Ховеры заработали, а свёрнутое содержимое перестало ловить фокус.

  **Ховеры.** Базовый вид компоненты пишут в атрибут `style`, а объявление таблицы стилей
  проигрывает атрибуту `style` по каскаду — до специфичности дело не доходит. Из-за этого
  двенадцать состояний указателя существовали в `ds.css` и не делали ничего: ховеры
  secondary и ghost кнопки, кнопки с тоном, циклера, опции группы, рамки поля, заголовка
  раскрывашки. У свойств, которые компонент пишет инлайном, теперь стоит `!important`.

  Отдельно: селектор `[data-tone]` сужен до поимённых `ok` и `danger`. Атрибут пишется
  всегда, включая `default`, поэтому у самой частой кнопки системы ховер был не тот, что
  объявлен, — а в светлой теме никакой вовсе (умножение яркости на почти чёрной заливке
  не даёт ничего).

  Возвращены три ховера, потерянные при переезде состояний в `ds.css`: вкладка `Tabs`,
  кнопка ⓘ в ряду, кнопка очистки поля. Значения взяты из разметки эталона.

  **Свёрнутое содержимое.** `Disclosure`, `RowInfo`, `RowMsg` и уходящий `Toast` прячут
  содержимое высотой — пиксели исчезали, узлы оставались. Значит оставались и в порядке
  таба, и в дереве доступности: фокус проваливался в невидимое, скринридер читал закрытую
  подсказку как обычный текст. Теперь свёрнутая область несёт `inert`.

  Оба дефекта были не теоретическими: в витрине таб уходил в невидимые поля и слайдеры
  блока «Примеры» и до следующей кнопки не доходил.

- 233ada4: Клавиатура ⓘ и таймер тоста.

  **Enter на ⓘ переключал ряд.** Ряд-переключатель сам себе контрол, но внутри него живёт
  кнопка подсказки, и событие с неё всплывает в ряд. Обработчик ряда делал две вещи разом:
  переключал ряд и гасил событие через `preventDefault` — второе отменяло активацию самой
  кнопки. То есть с клавиатуры подсказка не открывалась вовсе, а вместо неё переключался
  тоггл. Мышью всё работало: клик из ⓘ ряд у себя отфильтровывал, клавиатуру фильтровать
  забыли. Теперь обработчик клавиш ряда работает, только когда цель события — сам ряд.

  **Тост под `prefers-reduced-motion` исчезал мгновенно.** Автозакрытие висело на
  `animationend` полосы таймера, то есть клоком была анимация, а глобальное правило гасит
  анимации до 0.01 мс. Сообщение уровня danger было нечитаемым в принципе: настройка
  «поменьше движения» отбирала не движение, а содержание. Клок теперь JS-таймер, полоса
  осталась его показанием и под reduced-motion стоит на месте. Наведение останавливает и
  полосу, и отсчёт — остаток времени запоминается, а не начинается заново.

## 0.2.0

### Minor Changes

- 222905c: **Наружу теперь выходит не только `style`.** Каждый компонент принимает `className`, `id`, `data-*` и `aria-*` и кладёт их на корень. До этого `aria-label` и `data-testid` проходили проверку типов и молча терялись: потребитель получал поле без доступного имени и тест-сьют, которому не за что зацепиться, `react-hook-form` не подключался, `aria-describedby` к внешнему сообщению не привязывался. Опечатка в имени пропа в разметку по-прежнему не уезжает — берутся именно эти каналы, а не «всё лишнее».

  **`Toast` по умолчанию тухнет через 8000 мс**, как и обещала документация: в коде стоял `0`, то есть тост висел вечно.

  **Ряды `Island` получили устойчивый ключ.** Индекс прилипал к позиции, и при вставке или сортировке черновик неуправляемого поля, галочка и открытая ⓘ переезжали на соседний ряд. Появился проп `key` у ряда; без него ключ собирается из типа и подписи.

  **Сообщение `PinCard` принимает `author`** — как называется человек у `Avatar`, `PinComposer` и самой карточки. Прежнее `name` продолжает работать.

  **SSR больше не печатает предупреждение на каждый рендер:** `useLayoutEffect` подменяется на `useEffect` там, где DOM'а нет.

### Patch Changes

- 38d9bbb: Гейты доступности и оптики теперь проверяют то, что уезжает потребителю. `axe` до сих пор ходил только по замороженному эталону — вычисленное дерево доступности React-версии не проверял никто; оптическая центровка проверялась там же. Оба гейта гоняются по обеим реализациям, записи ledger'а ведутся раздельно.
- 38d9bbb: Стили витрины уехали из дизайн-системы в свой файл: `ds.css` потребителя больше не содержит правил про `<main><section>`, демо-дорожку изингов и маркеры списков. Костыль, вырезавший их при сборке, снят — вырезать нечего. Заодно удалены правила плавающего лейбла, которого в системе нет вовсе.
- ad3113d: Гейты перестали видеть одну-единственную конфигурацию пропсов. Паритет сверяет компонент во всех значениях его enum-пропсов и во включённых булевых состояниях — список выводится из контракта, поэтому растёт вместе с компонентом сам. Контрактный линтер пошёл по React-исходникам: проп, объявленный и не разбираемый, и имя из запрещённого словаря теперь краснеют и там. Снимки `reduced-motion` сверяются с обычными, а не сами с собой.

### Patch Changes

- 421d10d: Правки по консилиуму критиков.

  **Ряды острова, заданные конфигом без колбэка, больше не мертвы.** В React признак управляемости — значение, а остров отдавал вниз `checked`/`value` безусловно: тоггл, чекбокс и сегменты показывали ровно переданное, а менять их было нечем — ряд подсвечивался, продавливался, озвучивал `role="switch"` и не переключался.
